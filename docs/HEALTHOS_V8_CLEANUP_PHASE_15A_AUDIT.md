# HealthOS V8 Cleanup Phase 15A Audit

## Scope

This audit covers repository hygiene and safe cleanup after the HealthOS V8 Expo conversion. It does not change routes, app behavior, backend logic, dependencies, feature screens, database schema, or the legacy web tree.

## Summary Of Files Removed

The following generated and local runtime artifacts were removed:

- `.expo/`, including generated typed routes, device history, and Expo CLI logs
- `expo-dev*.log`
- `expo-step*.log`

These files are generated by local Expo CLI runs and are not source files. Expo will recreate `.expo/` and its typed route definitions when needed.

## `.gitignore` Changes

Added:

- `.expo/`
- `expo-dev*.log`
- `expo-step*.log`
- `*.err.log`
- `*.out.log`
- `.DS_Store`

Existing build and local ignores for `.next/`, `dist/`, `out/`, `web-build/`, environment files, package-manager logs, and `tsconfig.tsbuildinfo` remain in place.

## Active App Tree Decision

The active application is the Expo Router app under `src/app`.

Evidence:

- `package.json` uses `expo-router/entry`.
- Expo Router prefers `src/app` when that directory exists.
- The generated `.expo/types/router.d.ts` route map contained `src/app` routes such as `/(tabs)/today`, `/health-calendar`, and `/settings/coming-later`.
- The generated route map did not contain root-only legacy routes such as `/assistant`, `/tabs/home`, or `/settings/about`.
- `tsconfig.json` includes `src/**/*.ts`, `src/**/*.tsx`, and generated `.expo/types/**/*.ts`.
- `tsconfig.json` does not include root `app/**/*.tsx`, root `components/**/*.tsx`, or root `lib/**/*.ts`.
- `npm run typecheck` therefore checks the converted native app and its `src/` dependencies, but not the legacy root app tree.

### Root App Vs Src/App Decision

`src/app` is the actual converted HealthOS V8 native Expo app.

Root `app/` is a tracked legacy/duplicate route tree. It contains older routes such as `app/tabs/home.tsx`, `app/tabs/care.tsx`, and legacy settings routes. It is not represented in Expo's active generated route map and is not checked by the current TypeScript configuration.

Decision for Phase 15A:

- Keep root `app/` unchanged.
- Do not move or delete any root routes in this phase.
- Recommend moving root `app/` to `_archive/legacy-root-app` in a later phase only after a clean build, route smoke test, and explicit confirmation that no external tooling consumes it.

## TypeScript And Expo Router Findings

- TypeScript correctly checks the active `src/` native application.
- Generated `.expo/types` is safe to remove from git because it is regenerated by Expo CLI.
- Keeping `.expo/types/**/*.ts` in `tsconfig.json` is valid even while `.expo/` is ignored; the include becomes active whenever Expo regenerates the files.
- Root legacy application files are currently outside TypeScript coverage. This is intentional for the active native app, but it means legacy-tree breakage will not be caught by `npm run typecheck`.

## UI Duplication Report

### Canonical Native Components To Keep

The canonical HealthOS V8 native UI primitives live under `src/components/ui`:

- `AppScreen`
- `AppHeader`
- `AppCard`
- `AppButton`
- `AppChip`
- `AppIcon`
- `AppIconButton`
- `AppSection`
- `AppText`
- Native state, avatar, progress, widget, and form primitives

The canonical native barrel is `src/components/ui/index.ts`.

### Compatibility Wrappers To Keep Temporarily

Root `components/ui` contains native compatibility wrappers and older native primitives, including:

- lowercase wrappers such as `app-button.tsx`, `app-card.tsx`, and `app-header.tsx`
- casing duplicates such as `AppHeader.tsx` and `app-header.tsx`
- old/new pairs such as `HealthCard.tsx` and `health-card.tsx`
- compatibility exports in `components/ui/index.ts` and `components/ui/native.ts`

These should remain temporarily because the legacy root app and older modules may still import them.

### DOM/Web Components To Keep Isolated

Root `components/ui/web.ts` explicitly exports DOM/Radix components such as:

- `alert.tsx`
- `button.tsx`
- `card.tsx`
- `dialog.tsx`
- `input.tsx`
- `label.tsx`
- `select.tsx`
- `sheet.tsx`
- `tabs.tsx`
- `textarea.tsx`

These files should remain isolated from `src/` native imports.

### Risky Duplicates Not Deleted

No UI components were deleted in Phase 15A. Casing duplicates and compatibility wrappers are risky on cross-platform filesystems and should be handled only after usage mapping and legacy-tree archival.

## Native/Web Import Boundary Report

No unsafe web-only imports were found in the converted `src/` native application.

The following web-only technologies remain confined to the legacy root layer:

- Radix in root `components/ui`
- Next navigation, links, server APIs, and headers in root `app/`, `components/`, and `lib/`
- React DOM form hooks in root components
- Recharts and Framer Motion in root dashboard components
- Sonner in root form components
- `window.localStorage` and other browser APIs in root legacy libraries

No boundary fixes were necessary in Phase 15A.
